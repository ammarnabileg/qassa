# تقرير المرحلة 3 — التشغيل

## ما تم تنفيذه (مختبر)

| البند | التنفيذ | الدليل |
|---|---|---|
| **الحجز بدون تعارض** | زيارة فيها أكثر من خدمة، كل خدمة بموظف ووقت متتالي. قاعدة البيانات نفسها تمنع موظفًا في موعدين متداخلين (Exclusion constraint)، والإلغاء يحرر الوقت | `test_no_double_booking_and_cancel_frees_the_slot`، **6 حجوزات متزامنة لنفس الوقت → واحد ينجح** `test_concurrent_bookings_for_the_same_slot_only_one_wins` |
| قواعد الحجز | الموظف لازم يقدم الخدمة ويشتغل في الفرع، والخدمة لازم تكون لنفس نوع نشاط الفرع، ولا حجز في وقت فات، والإلغاء أو عدم الحضور بسبب | `test_booking_validates_skill_branch_and_business_type`، `test_status_flow_and_bad_transition` |
| الطابور | لوحة (منتظرين / على الكرسي / خلصوا) زي التصميم، و«خلص — للكاشير» ينقل الخدمات والموظفين للفاتورة | اختبار المتصفح |
| **الكاشير** | السعر من قائمة الأسعار على الخادم وقت البيع، وليس من الواجهة. لو السعر اتغير أثناء البيع ← 409. الخصم في حدود الدور أو بصلاحية تجاوز. ترقيم فواتير بدون فجوات. Idempotency | `test_prices_come_from_the_server_and_old_invoices_keep_their_price`، `test_discount_limit_and_override`، `test_checkout_is_idempotent_and_overpayment_refused` |
| الدفع | نقدي، أو كي نت (رقم الموافقة إلزامي لأن الجهاز غير متكامل)، أو تحويل، أو نقدي + كي نت، أو آجل (بصلاحية ولعميل مسجل) | الأمثلة 1 و3 و4 |
| المرتجع | إشعار دائن على سطر الفاتورة، والفاتورة الأصلية لا تتغير أبدًا. استرداد اختياري لا يتجاوز المدفوع | المثال 7 |
| الوردية | وردية مفتوحة واحدة لكل فرع، ولا كاش بدونها. المتوقع مقابل الفعلي. **الفرق يعتمده شخص غير اللي شغّل الوردية** ويُقيد على حساب عجز وزيادة الصندوق | `test_drawer_close_variance_needs_another_person_and_posts_over_short`، `test_manager_cannot_approve_own_drawer` |
| **القيود التلقائية** | لكل حدث قيد متوازن عبر أدوار الحسابات، ومرة واحدة فقط: الفاتورة (ذمم/إيراد)، والتحصيل (صندوق/كي نت/بنك مقابل ذمم)، والمرتجع، والاسترداد، وفرق الصندوق. الخصم يقلل الإيراد | ميزان المراجعة في اختبار المتصفح متوازن، وذمم العملاء = صفر بعد التحصيل |
| عدم التلاعب | الفواتير والسطور والمدفوعات والإشعارات الدائنة لا تُعدل ولا تُحذف حتى بـSQL مباشر | `test_issued_documents_are_immutable_in_the_database` |
| تطبيق العملاء | على التصميم الأساسي: خط Alexandria، والألوان، وشعار لكل نشاط | 5 اختبارات Flutter + لقطات |

**النتيجة:** 85 اختبار Backend + 5 Frontend + 5 Flutter، كلها ناجحة. واختبار متصفح كامل: وردية ← انتظار ← كرسي ← كاشير (باقي للعميل) ← إيصال ← دفع مختلط ← مرتجع واسترداد ← تقفيل بعجز ← ميزان المراجعة.

## مهم: القيود مقترحات
أدوار الحسابات والمعالجة (مثلًا: الخصم يقلل الإيراد، الفاتورة والتحصيل قيدان منفصلان) هي المقترحة في `ARCHITECTURE.md §6`. **لازم محاسب يراجعها قبل الاعتماد على التقارير المالية.**

## لم يُنفذ في هذه المرحلة (صراحة)
| البند | السبب |
|---|---|

| بيع المنتجات والمخزون والعمولات والإكراميات | المرحلة 4 |
